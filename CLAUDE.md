# The Analytics (anciennement "Analyste") — Outil d'analyse d'actions

## Contexte
Application personnelle web construite avec Claude (dans le chat claude.ai) pour remplacer un carnet papier d'analyse d'actions, méthode value/quality façon Buffett/Lynch. Le projet a été développé progressivement sur une longue conversation, feature par feature, à la demande de l'utilisateur (Nolan). On bascule maintenant sur Claude Code pour continuer le développement avec un vrai suivi de fichiers/Git.

## Stack technique — volontairement minimaliste
- **Un seul fichier `index.html`** autonome : HTML + CSS + JS inline, aucun framework, aucun build step.
- **Aucune dépendance externe** sauf Google Fonts (Inter pour l'interface, Source Serif 4 pour les titres, IBM Plex Mono pour les chiffres et tickers) chargées via `<link>`.
- **Stockage** : `localStorage` uniquement (clé `carnet-analyse-data-v1`), pas de backend.
- **PWA** : `manifest.json` + `service-worker.js` + `icon-192.png`/`icon-512.png` pour l'installation en application (hors-ligne, icône bureau). Prévu pour être hébergé sur GitHub Pages.
- Ne PAS introduire de framework (React, etc.) ni de build tool sans demande explicite — c'est un choix assumé de simplicité.

## Modèle de données
```
state = { companies: [Company...], activeId: string|null }
Company = {
  id, name, createdAt, updatedAt,
  currency: '$' | '€',  // devise unique de toute l'analyse, choisie à la création (voir plus bas)
  fields: { identite: {...}, financier: {...}, croissance: {...}, valorisation: {...}, personnelle: {...} },
  customFields: { identite:[], financier:[], ... },  // champs ajoutés librement par l'utilisateur
  position: { active, quantite, prixAchat, montantInvesti }  // toujours dans `currency`, plus de devise par ligne
}
```
- 5 sections fixes définies dans `const SECTIONS = [...]`, chaque champ a un `type` qui pilote son rendu (`text`, `textarea`→contenteditable riche, `number`, `duo`, `growthDuo`, `sharesTrio`, `wallStreetTrio`, `checklist`, `stars`, `moat`, `ceoFondateur`, `pieChart`, et plusieurs types `computed-*`).
- **Toujours ajouter une migration dans `migrateCompany(c)`** quand on change la forme d'un champ existant (voir les nombreux exemples dans la fonction) — ne jamais faire perdre de données déjà saisies par l'utilisateur.
- Une section 6 "Synthèse globale" (`buildInsightsSection`) calcule des insights à partir des données déjà saisies (carte récapitulative `buildGlobalRecap`, radar, profil de risque, objectif d'achat, résumé rédigé ; la plus/moins-value latente n'y est PLUS, elle est dans le bloc Position) — ne pas y ajouter de nouveau champ éditable, elle est 100% dérivée. La carte récapitulative marine est le même composant `buildRecapCard` que l'aperçu illustratif de l'accueil (données fictives) : modifier l'un modifie l'autre.
- Barre latérale "Mes analyses" : aucune pastille de couleur (choix de l'utilisateur). Affiche par contre, à droite du nom, la note de conviction en petites étoiles (`starsRowHtml`, classe `.si-stars`), uniquement si une conviction est renseignée. Les étoiles sont des SVG symétriques (`STAR_SVG`) pour que la demi-étoile soit coupée pile au centre ; `starsRowHtml(n, extraCls, id)` est la fabrique commune utilisée à la fois par le champ Conviction et la barre latérale, ne pas dupliquer la boucle de 5 étoiles ailleurs.
- **Tri de "Mes analyses" (barre latérale)** : bouton à double flèche (haut/bas) à droite du titre, qui ouvre un petit menu (`#sortMenu`, `paintSortMenu`, `setSidebarSort`) : critère (`SORT_KEYS` : date de création, ordre alphabétique, note en étoiles, dernière modification) puis sens, avec des libellés adaptés au critère (A → Z / Z → A, plus récentes d'abord...). Choix mémorisé dans `state.settings.sortKey`/`sortDir` (défaut `created`/`asc` = ordre d'ajout, comme avant). Changer de critère remet son sens naturel (alphabétique et création croissants, note et modification décroissants). Le tri ne s'applique qu'à la liste de la barre latérale (`sortedForSidebar`, utilisée par `renderTabs`), jamais à `state.companies` lui-même. Les analyses sans note restent toujours en bas. `touchUpdated` enregistre aussi `c.updatedTs` (horodatage précis) car `updatedAt` n'a que la précision du jour.
- **Symbole de devise affiché automatiquement** : tout champ qui représente un montant reçoit le marqueur `money:true` dans sa définition `SECTIONS` (ou sur le `sub` concerné pour un `duo`, ex. `dateIPO.prixInitial`). `render()` affiche alors `c.currency` juste après le champ (`.value-suffix` pour le rendu générique et `number-ecart`, un `.value-suffix` aussi dans un `duo`) — aucune saisie du symbole n'est nécessaire. Champs marqués `money:true` : `marketCap`, `dateIPO.prixInitial`, `chiffreAffaires`, `beneficeNet`, `fcf`, `capex`, `totalActif`, `detteNette`, `detteTotal`, `epsActuel`, `epsEstime1an`, `valorisationDcf`, `valeurIntrinseque`, `prixAchatCible` (`prixActuel`, la position et les champs déjà calculés ont leur propre affichage de devise, voir plus bas). Les ratios et comptages sans unité (PEG, bêta, dette nette/FCF, PE, nombre d'actions...) n'ont pas ce marqueur.
- **Nb d'actions (`sharesTrio`) : "Disponible" est calculé, plus saisi** (demande de Nolan le 2026-09-24) : Free Float et Closely Held sont des nombres d'actions saisis (formats `9 Md`, `900M`, lus par `parseMoney`), et `computeDisponible(c)` donne Free Float ÷ (Free Float + Closely Held) en % (vide tant que les deux ne sont pas renseignés). Affiché en case calculée (`#computed-financier-nbActions-dispo`) avec une pastille NEUTRE bleue (`pill-watch`, jamais vert/rouge, car un flottant faible n'est pas "mauvais" en soi) : moins de 50 % "Capital très concentré", 50 à 80 % "Flottant modéré", plus de 80 % "Flottant large, titre liquide" (`disponibleLabel`, infobulle `tipDisponible`). Rafraîchi par `refreshAllComputed`. L'ancienne valeur saisie `nbActions.disponible` n'est plus lue ni affichée (inoffensive dans les données existantes).
- **Symbole % affiché automatiquement (même principe que `money:true`)** : marqueur `percent:true` sur le champ (ou le `sub` d'un `duo`, ex. `croissanceCA.subs.cagr`), qui ajoute un `<span class="value-suffix">%</span>` après le champ, y compris pour les champs à barème (`value-with-badge`, la pastille colorée vient après). Aucune saisie du signe % n'est nécessaire. Champs marqués `percent:true` : `margeBrute`, `margeNette`, `roe`, `roic`, `positionShort`, et les subs `cagr` de `croissanceCA`/`croissanceBenef`/`croissanceAttendueCA`/`croissanceEstimeeEps`. Ces quatre champs sont de type `growthDuo` (`croissanceEstimeeEps`, section Valorisation, 3 ans, est devenu `{ cagr, total }` le 2026-09-25 avec migration de l'ancien nombre simple vers `cagr` : le PEG ne change pas ; `computePeg` = PE ÷ le CAGR, JAMAIS le total) (depuis le 2026-09-25 : avant, le "Total" de `croissanceCA`/`croissanceBenef` était saisi à la main) : seul le CAGR est saisi (avec son `%` en `.value-suffix`), le "Total" est CALCULÉ `(1 + CAGR)^années − 1` (`growthTotalText`, années = `field.years`, 5 ans pour le CA et les bénéfices, 3 ans pour le CA attendu), affiché dans une case bleue suivie du même `%` en `.value-suffix`, mis à jour par `refreshAllComputed` pour tout champ `growthDuo`. Un ancien "Total" saisi reste dans les données mais n'est plus lu ni compté dans le remplissage (`isFieldFilled` ne regarde que `cagr` pour `growthDuo`). Tout nouveau champ monétaire ou en pourcentage doit recevoir `money:true`/`percent:true`.
- **Visibilité des symboles $ et %** : `.value-suffix` (utilisée pour toutes les unités : devise, %, bêta `β`...) est volontairement plus affirmée que les autres légendes de l'app : `color:var(--ink)` (texte plein contraste, pas `--ink-soft`) et `font-weight:700` à 15px, pour que le symbole se voie au premier coup d'œil à côté du chiffre au lieu de se fondre dans le fond (demande de Nolan le 2026-09-23, "les rendre plus visible"). Ne pas réutiliser `.value-suffix` pour autre chose qu'une unité de mesure, sous peine de la rendre disproportionnée.
- **Devise unique par analyse** (`c.currency`) : choisie dans la modale "Nouvelle analyse" (mémorisée dans `state.settings.defaultCurrency` pour la prochaine fois) et modifiable à tout moment via la bascule `$`/`€` en haut de la fiche (`#companyCurrencyToggle`, fonction `setCompanyCurrency`). Elle remplace les anciens sélecteurs de devise par champ (prix actuel, prix d'achat, montant investi) : tous les montants d'une même analyse s'affichent automatiquement dans `c.currency`, plus besoin d'écrire le symbole. Changer la devise ne convertit PAS les montants déjà saisis (juste leur étiquette et les calculs d'affichage) — c'est volontaire, il n'y a pas de taux de change dans l'app. `formatMoneyDisplay(n, currency)` et tous ses appelants doivent recevoir `c.currency` explicitement (pas de valeur par défaut cachée). `migrateCompany` valide strictement `c.currency` (seulement `'$'` ou `'€'`, tout le reste retombe sur `'$'` ou sur l'ancienne devise par champ si elle existe) et supprime les anciens champs `prixActuelDevise`/`prixAchatDevise`/`montantInvestiDevise`.

## Conventions établies (à respecter)
- **Langue** : tout en français.
- **Champs (depuis l'identité visuelle v2)** : label au-dessus de la valeur (14px, semi-gras, pastille "i" quand une infobulle existe), valeur dans un champ encadré (15px, Inter). Les valeurs calculées automatiquement gardent leur fond bleu clair (`--calc-bg`/`--calc-text`), jamais en gras. **Grille des sections (refonte de mise en page du 2026-09-24)** : `.section-body` est une grille à 12 colonnes ; un `.field-row` prend 4 colonnes par défaut (3 par ligne), et chaque champ de `SECTIONS` peut porter `span` (3, 4, 6 ou 12, posé en `data-span` par la boucle de rendu) pour aligner des indicateurs similaires côte à côte (ex. ROE/ROIC/marges, 4 par ligne) et `group` (sous-titre pleine largeur `.field-group`, teinté de `var(--sec-c)`, inséré quand le groupe change). Les champs larges (texte riche, camembert, liste, checklist, image, MOAT, répartition des actions) restent sur toute la largeur via `:has(:where(...))` dans `.field-row` (le `:where` annule la spécificité pour qu'un `data-span` puisse les remettre sur une demi-largeur, ex. deux textes côte à côte ; les deux camemberts "Revenu par source/pays" restent volontairement l'un sous l'autre, pleine largeur, faute de place côte à côte, demande de Nolan). L'ordre des champs dans `SECTIONS` peut être changé librement (les données sont indexées par clé). Sous 1180px : 2 colonnes, sous 640px : 1 colonne ; chaque nouveau champ doit recevoir un `span` et si possible un `group` cohérents pour ne pas laisser de trou dans la grille. Attention : tout `.field-row` posé dans une AUTRE grille (comme `.position-fields`, 3 colonnes) doit remettre `grid-column:auto`, sinon le `span 4` y crée des colonnes implicites. Dans Mon espace, `.sgrid` est aussi à 12 colonnes (`.s5`/`.s6`/`.s7`/`.s12`) : associer les cartes par paires (5+7, 6+6) pour éviter une carte seule sur une ligne.
- **Largeur des champs courts (Chiffres, %, ticker, dates courtes) vs champs de texte libre** : un champ dont la donnée est courte par nature est petit par défaut et s'agrandit avec la saisie (attribut HTML `size`, recalculé en direct par les listeners génériques `if(el.hasAttribute('size')) el.size = ...`), pour que le symbole de devise ou le badge de barème reste collé au chiffre. `fieldInput()` pose `size` dans quatre cas : `type:'number'`/`'number-ecart'` (plancher 2 caractères), `type:'ticker'` (plancher 3), `field.money` en texte libre comme `chiffreAffaires` (plancher 4), et `SCALE_CONFIG[field.key] || field.compact` pour un champ court non monétaire comme `margeBrute`/`ratioVenteADecouvert`/`dateCreation` (plancher 3, `field.compact` est un marqueur ad hoc pour un champ ponctuel sans autre raison d'être court). Pour un `duo` (ex. `dateIPO`, `croissanceCA`), `compactSub = field.autoWidth || sub.money || SCALE_CONFIG[field.key]` déclenche la même classe `.duo-item-auto` sur le sub concerné. Depuis le 2026-09-24, ces cases utilisent en plus `field-sizing:content` (bloc CSS juste avant `.value-with-note`, largeur exactement égale au texte, marge intérieure réduite à 11px, `min-width:38px`) : l'espace entre le dernier chiffre et le symbole $ ou % vaut 6px au total (`.value-suffix` `margin-left:6px`, `-6px` dans `.value-with-badge` qui a déjà un `gap:12px`). L'attribut `size` n'est plus qu'un repli pour les navigateurs sans `field-sizing`. Le filet CSS général `.field-value > input[size]{width:auto !important;min-width:56px}` (enfant DIRECT de `.field-value`, pour ne pas interférer avec les habillages `.value-with-suffix`/`.value-with-badge`/`.value-with-ecart` qui gèrent déjà leur propre largeur au même min-width) couvre tout champ court qui n'a pas d'habillage dédié. Un champ de texte libre (secteur, pays, siège social, notes) reste volontairement pleine largeur : ne pas lui ajouter `size`, `money`, ni `compact`.
- **Quand une infobulle s'affiche (demande de Nolan le 2026-09-23)** : sur un libellé de champ, uniquement au survol direct du petit "i" (pseudo-élément `.field-label[data-tooltip]:after`, repéré par la position du curseur dans `initCustomTooltips`/`overInfoIcon` ; le libellé est réduit à son contenu par `align-self:flex-start` pour que le "i" en occupe la fin), plus au survol des cases calculées automatiquement (`.computed`, `.ecart-slot`). Survoler le texte du libellé n'affiche rien. Les autres `data-tooltip` (pastilles de barème, boutons, en-têtes de tableau, bascule de devise, avatar) restent au survol direct de l'élément.
- **Écart cours / valeur estimée ("vs DCF", "vs Intrinsèque", `computeEcart`, corrigé le 2026-09-25 à la demande de Nolan)** : résultat signé, négatif = sous-évaluation, positif = surévaluation. Sous-évaluation = `(prix − valeur) ÷ valeur` (marge de sécurité, jamais plus de 100 %). Surévaluation = `(prix − valeur) ÷ prix` (de combien le cours devrait BAISSER pour rejoindre la valeur, toujours sous 100 %) ; avant, on divisait aussi par la valeur, ce qui donnait +100 % pour un cours du double de la valeur alors qu'une baisse de 50 % suffit. Valeur nulle ou négative : pas de calcul. Tous les appelants gardent la même convention de signe (seuils : marge de sécurité de Buffett quand `e < -0.05`, alerte Portefeuille quand `e > 10`, décote quand `e <= -15`) ; les textes qui parlaient d'un cours "au-dessus de la valeur de X %" disent maintenant que le cours "devrait baisser de X %". `tipEcart` affiche la formule du côté concerné. Les textes de la section Apprentissage (formule de la marge de sécurité, dictionnaire de `valeurIntrinseque`) donnent les deux formules.
- **Résumé de valorisation (`buildValuationSummaryBlock`, chips `.vs-chip`, revu les 2026-09-25 et 2026-09-26 à la demande de Nolan)** : 8 chips (2 lignes pleines de 4, ajout du PE forward pour combler la case vide), dans l'ordre : PE (actuel, sans couleur), PE forward, PEG, PE / Secteur, vs Intrinsèque, Wall St. moy (% calculé), Consensus (titre anglais de la jauge, dans sa couleur, petite police `.vs-value-sm`), Position short (`%`, couleur du barème `positionShort`). MOAT et "vs DCF" ont été retirés : le DCF dépend trop des hypothèses, la valeur intrinsèque est la référence partout dans l'app (marge de sécurité, alertes, Mon espace) ; les deux champs de saisie DCF et Valeur intrinsèque, eux, restent. Grille de 4 colonnes (3 puis 2 en dessous de 1180 et 640 px). Rafraîchi par `refreshValuationSummary` (appelée par `refreshDerived`, par la saisie des cases Wall Street et par `setWsReco` au relâchement de l'aiguille).
- **Wall Street, disposition (2026-09-25)** : `.ws-top` = grille de deux colonnes (sous 1180 px : une seule) : à droite la carte "Prévision long terme" (`buildWsLongTerm`, `wsLtIndicatorsHtml`, `computeLongTerm`, `#wsLongTerm` ; remplace la carte "Potentiel à 1 an" jugée peu utile par Nolan le 2026-09-26). Deux cases de saisie, `wallStreet.ca5` (chiffre d'affaires annuel estimé dans 5 ans) et `wallStreet.benef5` (bénéfice net annuel estimé dans 5 ans), acceptent les unités (`700 Md`, `190B`, comptent dans le remplissage), puis des indicateurs CALCULÉS avec les chiffres actuels de la section Financier (`chiffreAffaires`, `beneficeNet`, `margeNette` en repli) et le Market Cap de la section IDENTITÉ (`identite.marketCap`, repli sur `financier.marketCap`) et le prix actuel : CAGR implicite du CA et du bénéfice net sur 5 ans `(estimé ÷ actuel)^(1/5) − 1`, colorés avec les barèmes `croissanceCA` et `croissanceBenef` ; marge nette dans 5 ans (`bénéfice ÷ CA`, barème `margeNette`, comparée à la marge actuelle en points) ; PE sur le bénéfice futur (`capitalisation ÷ bénéfice estimé` ; SANS capitalisation renseignée, repli sur `PE actuel × bénéfice actuel ÷ bénéfice estimé`, champ `pe5Src` 'cap' ou 'pe' ; comparé au PE actuel) ; cours théorique dans 5 ans à PE constant (`cours actuel × bénéfice estimé ÷ bénéfice actuel`, sans dividende ni variation du nombre d'actions, note affichée dans la carte). Seule la partie `#wsLtInd` est refaite pendant la frappe (`refreshWsPercents`), jamais les champs de saisie, sinon le focus serait perdu ; `compactMoney` formate 391 Md$, 2,85 T$. Sous 1180 px la carte passe sous les autres. et à gauche (`.ws-left`, 480 px maximum, le surplus de hauteur est réparti entre ses deux cartes pour aligner le bas) deux cartes de même largeur l'une sous l'autre : `.ws-cols` (UNE carte, trois colonnes `.ws-col` séparées par un filet fin, libellés écrits en entier « Maximum », « Moyenne », « Minimum » ; le prix cible en haut et, DESSOUS, le pourcentage calculé et sa pastille, pour bien distinguer les trois ; compacte, ~150 px de haut, sous 640 px les colonnes s'empilent) puis la carte de la jauge du consensus (texte à gauche, jauge de 200 px à droite, ~140 px de haut). ## Majuscule automatique (demande de Nolan le 2026-09-27)
Deux mécanismes coexistent, sans conflit (le second comble ce que le premier ne couvrait pas) :
- **Ancien (déjà présent avant cette demande)** : `updateField` appelle `capitalizeFirst(value)` sur CHAQUE frappe pour tout champ `fieldType === 'text'` (donc tous les champs posés par `fieldInput()` avec `data-type="text"` : texte libre, monétaires, courts, CEO...). `capitalizeFirst` cherche la PREMIÈRE lettre où qu'elle soit dans la chaîne et la met en majuscule, en continu (donc si on insère un caractère avant une majuscule déjà posée, celle-ci redescend et la nouvelle première lettre remonte). Les champs `ticker` (mis en MAJUSCULES entières) et `richtext` (`fieldType` vaut `'richtext'`, pas `'textarea'` : ce test ne le capturait donc jamais) ne sont pas concernés par ce mécanisme.
- **Nouveau (`initAutoCapitalize`, `shouldAutoCapitalize`, `autoCapitalizeFirst`)** : comble les cases que l'ancien mécanisme ne couvrait pas, à savoir les sous-champs `data-duo-sub` (industrie, siège social, précisions du dividende, croissance du dividende...), les zones de texte riche `.rich-textarea` (activité principale, thèse, autres activités...), le nom d'un segment de camembert (`data-pie-prop="label"`), une ligne de la liste Clients (`data-client-idx`) et un champ personnalisé (`data-custom-prop`). Contrairement à l'ancien, il n'agit qu'une fois, au moment précis où une case VIDE reçoit son PREMIER caractère (`value.length === 1` ou, pour le texte riche, `textContent.length === 1`) : il ne re-force jamais la majuscule plus tard, pour ne pas annuler une correction manuelle de l'utilisateur en cours de saisie. Volontairement exclu par construction (aucun des attributs recherchés) : e-mail, mot de passe, clé API Twelve Data, prénom des préférences, champs de recherche (`type="search"`), ticker, nombres, prix Wall Street, confirmation SUPPRIMER — pas de liste noire à tenir à jour, juste l'absence des attributs data-* ciblés.

## Graphique des prévisions Wall Street
Sous le champ `wallStreet` (Max/Moy/Min), `buildWallStreetChart(c)` dessine un graphique "en éventail" sur fond marine (carte `.ws-chart`) qui ressemble à un vrai graphique de prévisions boursières :
- **Saisie (changée le 2026-09-25 à la demande de Nolan)** : l'utilisateur saisit désormais les PRIX CIBLES à 1 an (Max, Moy, Min, en devise de l'analyse, avec le symbole automatique) et non plus les pourcentages. `computeWallStreetTargets(c)` lit ces prix (`parseMoney`) et calcule le % = `(prix cible ÷ prix actuel) − 1`, affiché automatiquement à côté de chaque case (`#ws-pct-max|moy|min`, case bleue calculée avec infobulle, plus une pastille de couleur `#ws-badge-*`, mises à jour par `refreshWsPercents`, appelée par `refreshWallStreetChart`). Barème (`wallStreetTier`/`wallStreetColor`/`wsScaleTooltip`) : négatif rouge (mauvais), 0 à moins de 10 % jaune (moyen), 10 à moins de 30 % vert clair (bon), 30 % et plus vert foncé (très bon) ; il colore aussi les rayons et bandes du graphique, qui lui n'a pas changé. Le résumé de valorisation ("Wall St. moy") et la phrase de synthèse utilisent le % calculé. **Migration** : avant, les cases contenaient des pourcentages. `wallStreet.unit === 'price'` marque le nouveau format ; `applyLegacyWallStreet(c)` (appelée par `migrateCompany`, au début de `render()` d'une fiche et après une mise à jour automatique du prix) convertit les anciens % en prix (`prix actuel × (1 + %/100)`, arrondi au centime) ; sans prix actuel, les anciens % sont gardés dans `wallStreet.legacyPct` (affichés dans une note sous les cases) puis convertis dès que le prix existe, jamais perdus. `updateWallStreetField` et `newCompany` posent toujours `unit:'price'`, sinon un prix saisi serait pris pour un ancien % au rechargement.
- **Jauge "Consensus des analystes" (2026-09-25)** : sous les cases Max/Moy/Min et au-dessus du graphique, carte marine `.ws-reco` (`buildWsGauge`, `paintWsGauge`, `setWsReco`, `bindWsGauge`) : demi-cercle de 5 zones Strong Sell, Sell, Hold, Buy, Strong Buy (titres en anglais, choix de Nolan ; couleurs `WS_RECO` : rouge, jaune, gris, vert clair, vert foncé, demande de Nolan le 2026-09-26 ; `color` = teinte vive sur la carte marine, `tier` = palier `TIER_COLORS` utilisé pour le texte sur fond clair dans le résumé de valorisation, via `wsRecoTextColor`) et une aiguille. Réglage MANUEL : clic, glissement (pointer events, `touch-action:none`) ou clavier (flèches, Maj pour 0,5, Home/End, Suppr) ; bouton "Effacer". Stockée dans `wallStreet.reco`, chaîne de 1 à 5 avec une décimale (1 = Strong Sell, 5 = Strong Buy), 5 zones égales de 0,8 point (`wsRecoIndex`, avec une marge 1e-9 contre l'imprécision flottante : Hold est centré sur 3). Vide : aiguille estompée et "Non renseigné". Enregistrée seulement au relâchement (pas à chaque mouvement). La phrase de synthèse la cite. `isFieldFilled` pour `wallStreetTrio` ne regarde que `max/moy/min/reco` (`unit` et `legacyPct` ne comptent pas). Le texte de la jauge est en HTML sous le SVG, pas dans le SVG.
- Quatre rayons partent tous du même point de départ (prix actuel, aujourd'hui) et rejoignent leur cible en ligne droite à +1 an : "Actuel" est plein et bleu (`#5b8cf7`), Max/Moy/Min sont pointillés et colorés avec le même `wallStreetColor()` que les champs eux-mêmes (rouge / jaune / vert clair / vert foncé selon le barème ci-dessus).
- Des bandes triangulaires transparentes remplissent l'espace entre rayons consécutifs (triés par prix cible), couleur de la borne haute (une bande qui redescend vers "Actuel" depuis une valeur négative reste rouge).
- Axe de prix à l'échelle (`niceAxisTicks`, graduations rondes 1/2/5×10ⁿ) avec grille de fond.
- **Important : les étiquettes (catégorie + % + prix cible, graduations de l'axe) sont des `<div>` HTML positionnés en `top`/`left` en pourcentage par-dessus le SVG (`preserveAspectRatio="none"`), PAS du texte SVG.** Un texte SVG hérite du facteur d'échelle du `viewBox`, donc devient illisible dès que la carte est étroite (mobile) ; le texte HTML garde toujours sa taille de police fixe (13-13,5px), quelle que soit la largeur du graphique. Ne jamais revenir à du texte inline dans le SVG pour ce graphique.
- `.ws-chart-inner` a un `min-height:320px` (en plus de `aspect-ratio`) pour garantir assez de place verticale aux étiquettes même sur un écran très étroit ; en dessous de 640px de large, les graduations de l'axe (`.ws-axis-tick`) sont masquées (redondantes avec les étiquettes) pour éviter tout chevauchement horizontal.
- Les étiquettes sont recalées verticalement (`labelYByKey`, calculé en triant par position à l'écran, PAS par prix — un prix plus élevé se dessine plus haut) pour ne jamais se chevaucher quand deux cibles sont proches.
- `refreshWallStreetChart()` (id `wsChartWrap`) est appelé après chaque saisie sur prix actuel ou max/moy/min.
